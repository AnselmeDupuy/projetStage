Company Information

Northwind Digital Services - Customer Platform

Location: Paris Regional Office

Incident Details

Customers experienced severe login delays on the portal after a degraded identity cache caused repeated fallback requests to the primary authentication store.

Start Time: 2026-03-11T11:56:10

Detection Time: 2026-03-11T12:07:02

End Time: 2026-03-11T14:39:08

Root Cause: A cache node memory leak forced repeated evictions, amplifying traffic to the authentication datastore.

  • Identity Cache
  • Authentication API

  • Identity Services
  • Customer Support

Timeline

  • 12:07 - Synthetic login probes exceeded latency threshold
  • 12:16 - Identity services engaged and cache metrics reviewed
  • 12:44 - Faulty cache node isolated from rotation
  • 13:28 - Additional auth API capacity added during recovery
  • 14:39 - Login latency returned to normal operating range

Resolution

Actions Taken

  • Removed the leaking cache node from service
  • Warm-loaded replacement cache instances
  • Applied temporary rate protection on fallback auth requests

Verification: Portal login tests passed from five regions, and support confirmed user sign-ins were succeeding without visible delay.

Resolved By: Identity Services Team

Postmortem

Lessons Learned

  • Cache health alerts should include eviction storms and memory leak indicators.
  • Fallback request protection needs to activate earlier to protect the primary datastore.

Preventive Actions

  • Deploy memory leak detection to the cache tier
  • Add adaptive throttling for auth fallback traffic
  • Expand regional synthetic login coverage

  • 22:08 - Duplicate settlement events identified in raw feed

  • 01:04 - Corrected ledger export delivered to accounting systems

  • Reprocessed the affected settlement window with deduplication enabled
  • Patched the retry path to preserve settlement idempotency

Resolved By: Data Engineering Team

Lessons Learned

  • Batch validation should stop downstream delivery before manual finance review is required.

Preventive Actions

  • Introduce immutable event replay identifiers across the settlement pipeline
  • Expand finance batch simulation tests for retry scenarios

  • Add fallback token refresh on scanner reconnect
  • Create an automated backlog replay verification job
